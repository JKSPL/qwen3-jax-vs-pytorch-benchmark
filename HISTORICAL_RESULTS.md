# Historical aggregate results

Hardware: 8 × NVIDIA L40S. Model shape: 12 layers, hidden size 768,
intermediate size 2304, 12 query heads, 6 key/value heads, vocabulary 32768,
sequence length 512, per-device batch size 2. Each measurement used 5 warm-up
steps and 30 timed steps on a fixed synthetic batch.

| Stage | Framework | Gradient communication | Process topology | Seconds/step | Tokens/s |
| --- | --- | --- | --- | ---: | ---: |
| Initial baseline | JAX | FP32 | 1 × 8 GPUs | 0.090571 | 90,448.7 |
| Initial baseline | PyTorch | FP32 | 8 × 1 GPU | 0.070733 | 115,816.6 |
| Compile/flash | JAX | FP32 | 1 × 8 GPUs | 0.087713 | 93,395.2 |
| Compile/SDPA | PyTorch | FP32 | 8 × 1 GPU | 0.064152 | 127,697.4 |
| Tuned runtime flags | JAX | FP32 | 1 × 8 GPUs | 0.076679 | 106,834.7 |
| BF16 gradients | JAX | BF16 | 1 × 8 GPUs | 0.044113 | 185,705.6 |
| BF16 gradients | PyTorch | BF16 | 8 × 1 GPU | 0.040957 | 200,013.8 |
| 64 MiB reduction threshold | JAX | BF16 | 1 × 8 GPUs | 0.043327 | 189,074.9 |
| FP32 gradient baseline | PyTorch | FP32 | 8 × 1 GPU | 0.061688 | 132,798.0 |
| 28 MiB reduction threshold | JAX | FP32 | 1 × 8 GPUs | 0.076752 | 106,733.0 |
| 28 MiB + communication split | JAX | FP32 | 1 × 8 GPUs | 0.076583 | 106,969.4 |
| Process-per-GPU | JAX | FP32 | 8 × 1 GPU | 0.060759 | 134,828.7 |
| Process-per-GPU repeat | JAX | FP32 | 8 × 1 GPU | 0.060789 | 134,760.7 |

The decisive finding was topology: matching PyTorch DDP with one JAX process per
GPU removed the apparent FP32-gradient disadvantage. The single-process JAX
profile had longer NCCL all-reduces, but that profile did not generalize to the
matched process topology.

## Limitations

- These are aggregate historical measurements, not outputs generated by this
  sanitized source tree.
- The original JAX implementation was coupled to an internal model package and
  was replaced here by a self-contained public-architecture implementation.
- Private experiment URLs, run identifiers, source revisions, paths, host
  identity, user identity, and GPU UUIDs were intentionally removed.
- CUDA, driver, NCCL, compiler, thermal, and background-load differences can
  materially change throughput. Re-run all arms on the same machine and window.
